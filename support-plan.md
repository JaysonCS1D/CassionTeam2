# Support Plan

## Project: Python Task Manager App

---

## 1. Issue Reporting Process

### Step 1 — Identify the Issue
- Bug: something is broken or not working
- Feature request: something is missing
- Performance problem: something is too slow

### Step 2 — Report the Issue
Create a GitHub issue with:
- Clear title describing the problem
- Steps to reproduce the issue
- Expected vs actual behavior
- Screenshots if applicable
- Severity level: Critical / High / Medium / Low

### Step 3 — Issue Triage
- QA Engineer (Member D) reviews new issues within 1 business day
- Issue is assigned a severity level and an owner
- Bug is added to docs/defect-log.md if confirmed

---

## 2. Severity Levels and Response Times

| Severity | Description                              | Response Time | Resolution Time |
|----------|------------------------------------------|---------------|-----------------|
| Critical | App is down or data loss is occurring    | 1 hour        | Same day        |
| High     | Major feature broken, no workaround      | 4 hours       | Within 1 day    |
| Medium   | Feature partially broken, workaround exists | 1 day      | Within 3 days   |
| Low      | Minor UI issue or cosmetic bug           | 3 days        | Next sprint     |

---

## 3. Escalation Path

1. Issue reported → QA Engineer (Member D) triages
2. If unresolved in response window → escalate to Lead Developer (Member B)
3. If still unresolved → escalate to Project Manager (Member A)
4. Critical issues → all team members notified immediately

---

## 4. Maintenance Windows

- Scheduled maintenance: Sundays 12:00 AM to 2:00 AM
- Users notified 24 hours in advance
- No maintenance scheduled during sprint demos or release windows
